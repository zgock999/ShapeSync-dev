ShapeSync VRM Integration Guide (vrm_en.html) - Chapter 3

This document is Chapter 3 of the ShapeSync documentation flow, covering the VRM avatar integration features (UniVRM Integration, VRM Initialize, Expression Baker, and Physics Transporter) for the 3D avatar dressing and body deformation middleware ShapeSync. Building upon the core concepts learned in tutorial_en.html (FBM foundation) and advanced_en.html (PBM / BCP / PCM), this guide explains the step-by-step workflow for VRM 1.0 structuration, MCM expression baking, and SpringBone physics transport.

1. Overview & Workflow Architecture

The official ShapeSync documentation is structured into the following 3 chapters:

Chapter 1: tutorial_en.html (Getting Started)
  └ Basic Figure creation, FBM (Full Body Morph) control, and basic Outfit (Shirt) attachment

Chapter 2: advanced_en.html (Advanced Features)
  └ Advanced topics: Partial Body Morph (PBM), Bone Correction Profile (BC Profile), and Mesh Clipping Prevention (PCM)

Chapter 3: vrm_en.html (VRM Integration) ← This Document
  └ VRM 1.0 structuration, MCM expression baking, and SpringBone physics transport & synchronization

The workflow directly maps to the 3-tab UI of the editor tool Tools > zgock > ShapeSync > VRM Transporter and the asset separation/transfer pipeline.

2. Prerequisites (UniGLTF & UniVRM)

To use ShapeSync VRM integration features, the following prerequisites are required in addition to the Core features:

  1. UniGLTF & UniVRM Package Installation:
    Ensure compatible UniGLTF and UniVRM 1.0 (UniVRM10) packages are installed in your project (UniGLTF is included as a dependency of UniVRM).
  2. Scripting Define Symbol Configuration:
    Add SHAPESYNC_USE_UNIVRM to Project Settings > Player > Script Compilation > Scripting Define Symbols, then click Apply.
  3. Launch Editor Tool:
    Open the editor window from the menu bar via Tools > zgock > ShapeSync > VRM Transporter.

3. VRM Transporter Overview & Recommended Workflow

The VRM Transporter window consists of the following 3 ordered steps structured as tabs:

Tab Order Tab Name Primary Purpose & Process Default Candidate Name
Step 1 VRM Initialize Builds VRM10Object, Vrm10Instance, and empty standard Expressions on ShapeSync Figure. <InputName>_VRMInit.prefab
Step 2 Expression Baker Bakes MorphTarget Expressions shared between Base and FBM target VRMs using MCM mechanism. <InputName>_ExpressionBaked.prefab
Step 3 Physics Transporter Transports Vrm10Instance.SpringBone physics and VRM10SpringBoneColliderGroup to Figure / Outfit. <DestinationName>_Physics.prefab
<DestinationName>_PhysicsOutfit.prefab

[Important Note on Technical Prerequisite]
While the recommended workflow order in this guide is VRM Initialize → Expression Baker → Physics Transporter, the **technical prerequisite for executing Physics Transporter is an "Initialized Figure (VRM Initialize completed)"**. Completing Expression Baker is recommended, but is not a strict technical prerequisite for running Physics Transporter.

4. Step 1: VRM Initialize (VRM Structure Setup)

To run a ShapeSync Figure created with Figure Builder as a VRM avatar, it requires a component structure matching the UniVRM 1.0 specification (VRM10Object asset, Vrm10Instance, Humanoid Avatar, and empty standard VRM10Expression assets).

* Note: VRM Initialize is a process that creates a clone of the input Figure and builds the VRM 1.0 structure from scratch. It does NOT transfer expression data from the source VRM. Expression data baking is performed in the next step, Expression Baker.

Operating Procedure (VRM Initialize Tab)

  1. Open the VRM Transporter window and select the VRM Initialize tab.
  2. Configure the fields:
    • Source ShapeSync Figure: Specify the Figure created in Chapter 1 (Tutorial), or if inheriting PBM / BCP / PCM for final integration, specify the Figure updated/regenerated in Chapter 2 (Advanced) in the Scene.
    • VRM Asset Relative Folder: VRM/ (relative output folder path)
  3. Click the "Create ShapeSync Ready VRM" button.
  4. A Save file dialog appears. Select your desired output path and filename (Default candidate: <InputName>_VRMInit.prefab).
  5. Result: Without modifying any BlendShapes or FBM data on the Figure, an Init Prefab containing VRM10Object, Vrm10Instance, Humanoid, and empty standard Expression assets is output and saved.

5. Step 2: Expression Baker (MCM Expression Baking)

When the character's face or head shape changes due to an FBM (e.g. BasicGirl), eye and mouth expression BlendShapes can conflict with body deformation. ShapeSync provides the Expression Baker to solve this. Using the MCM (Morph Controlled Morph) pipeline, Expression Baker analyzes and synthesizes expression assets between the Base VRM and all FBM target VRMs, ensuring expressions naturally conform to body shape changes across Base / FBM VRM configurations.

Specifications & Constraints

  • Applicable Scope: The baking process strictly targets **MorphTarget (BlendShape) Expressions shared across the Base VRM and all FBM source VRMs** (material-only or UV-only expressions are excluded). Custom expressions that do not exist in all FBM source VRMs are listed as skip candidates in the UI.
  • Face Renderer Alignment: The face Renderers of the Base VRM and all FBM source VRMs must correspond in vertex count and vertex positions with the Base and FBM face vertices of the Figure.
  • Generated BlendShapes: Synthesized BlendShapes with prefixes VRM_* and MCM_* are generated on the output mesh. Existing baked shapes with matching names are replaced on the output Prefab.

Operating Procedure (Expression Baker Tab)

  1. Select the Expression Baker tab.
  2. Configure the base references:
    • ShapeSync Ready Figure: Scene VRMInit Figure object created in Step 1
    • Figure Renderer: Face/Head SkinnedMeshRenderer of the Figure
    • Base VRM Renderer: Face/Head SkinnedMeshRenderer of BasicFemale
    • Base Source VRM: Original BasicFemaleHairAndSkirt.vrm object
  3. In the FBM Source VRMs section, click "Generate Target Entries".
  4. For the generated entry, set FBM BlendName to BasicGirl, Target VRM Renderer to the face Renderer of BasicGirl, and Source VRM to BasicGirlHairAndSkirt.vrm.
  5. Click the "Bake Expressions and Create Baked Prefab" button.
  6. A Save file dialog appears. Select your desired output path and filename (Default candidate: <InputName>_ExpressionBaked.prefab).
  7. Result: MCM expression baking completes, saving a baked Prefab where expressions stay naturally synchronized during FBM body deformations.

6. VRM Physics Asset Separation & Outfit Creation (Preparation)

Before transferring physics data with Physics Transporter, extract and separate the hair and skirt sway parts from the tutorial assets BasicFemaleHairAndSkirt.vrm and BasicGirlHairAndSkirt.vrm, and build them as independent ShapeSync Outfit Prefabs.

* Note on Single Renderer Constraint: The current Outfit Builder does not support Outfits containing multiple SkinnedMeshRenderer components. Therefore, the Hair and Skirt prefabs created in this procedure must be structured with a **single SkinnedMeshRenderer under each Outfit Root**.

Step 1: Hair Mesh Extraction & Prefab Creation

  1. Right-click BasicFemaleHairAndSkirt.vrm placed in the scene and execute Prefab > Unpack Completely.
  2. Delete unneeded objects except the Hair mesh and its corresponding hair bone hierarchy, leaving an independent GameObject containing a single SkinnedMeshRenderer.
  3. Drag and drop it into the Project window to save it as the hair prefab BasicFemale_Hair.prefab.

Step 2: Skirt Separation via Mesh Separation

  1. Open Tools > zgock > ShapeSync > Mesh Utility from the menu bar.
  2. Select the Mesh Separation tab.
  3. Assign the Body SkinnedMeshRenderer of BasicFemaleHairAndSkirt to the Source Renderer field.
  4. Select the target material slots (tutorial asset examples: Skirt or *_CLOTH_*).
  5. Click "Generate Separated Mesh Prefab" to save the single-renderer skirt prefab BasicFemale_Skirt.prefab.
Figure 6: Material Separation Setup in Mesh Separation (Separator) Tab

Step 3: Target VRM (BasicGirl) Asset Separation

  1. Perform Step 1 (Hair extraction) and Step 2 (Skirt separation) on the target BasicGirlHairAndSkirt.vrm.
  2. Save single-renderer prefabs BasicGirl_Hair.prefab and BasicGirl_Skirt.prefab.

Step 4: Outfit Creation via Outfit Builder

  1. Open Tools > zgock > ShapeSync > Outfit Builder from the menu bar.
  2. Configure the common Figure reference fields:
    • Figure Root: Specify the ShapeSync Figure used for final integration (Chapter 1 Figure, or the Figure updated in Chapter 2 Advanced if inheriting PBM / BCP / PCM).
    • Figure Animator: Specify the Humanoid Animator of the selected Figure.
  3. Hair Outfit Creation Order:
    1. Configure Figure Root and Figure Animator.
    2. Set Base Outfit Root to BasicFemale_Hair, Registry Id to hair-1, and Registry Name to Hair1.
    3. Click the "Generate Target Entries" button.
    4. In the generated BasicGirl row, assign BasicGirl_Hair to the Target Outfit Root field.
    5. Click "Generate SkinnedMesh Outfit Prefab" to build and save Hair_ShapeSyncOutfit.prefab.
  4. Skirt Outfit Creation Order:
    1. Configure Figure Root and Figure Animator.
    2. Set Base Outfit Root to BasicFemale_Skirt, Registry Id to skirt-1, and Registry Name to Skirt1.
    3. Click the "Generate Target Entries" button.
    4. In the generated BasicGirl row, assign BasicGirl_Skirt to the Target Outfit Root field.
    5. Click "Generate SkinnedMesh Outfit Prefab" to build and save Skirt_ShapeSyncOutfit.prefab.
Figure 7: Hair & Skirt Outfit Configuration and Target Outfit Root Assignment in Outfit Builder

7. Step 3: Physics Transporter (SpringBone Transport & Verification)

Use the Physics Transporter tab to transfer and apply Source VRM Vrm10Instance.SpringBone physics data (VRM10SpringBoneJoint and VRM10SpringBoneColliderGroup) to the Figure and Outfit Prefabs.

Operating Conditions & Attachment Specs

  • Source VRM Requirement: Must possess a valid Vrm10Instance and Vrm10Instance.SpringBone data.
  • Figure Mode Destination Requirement: Must be an Initialized Figure holding a valid Vrm10Instance and Animator.
  • Outfit Mode Destination Requirement: Must be a Scene Object, Scene Prefab instance, or Root in Prefab Mode (Project window Prefab assets cannot be assigned directly).
  • Canonical Spring Bone Source: Parameter for Figure Mode only (disabled in Outfit Mode).
  • Asset Storage & Embedded Specs: Transferred SpringBone data is directly embedded into the output Figure Prefab in Figure Mode, and embedded as Outfit SpringBone data in Outfit Mode (automatically connected by ShapeSync's companion system upon attachment). **No standalone physics sub-asset files are generated**.

Step 1: SpringBone Physics Transfer to Figure

  1. Open the Physics Transporter tab in the VRM Transporter window.
  2. Configure the fields:
    • Source VRM Root: Original BasicFemaleHairAndSkirt.vrm
    • Destination Figure Root: Scene Figure object created in Step 1 (or Step 2)
    • Destination Mode: Figure
    • Canonical Spring Bone Source: SourceVrm
  3. [Mandatory Verification] Click the "Validate / Dry Run" button. Confirm in the log dialog that there are no errors in SpringBone or ColliderGroup counts.
  4. Click the "Transfer" button. Select output path and filename in the Save dialog (Default candidate: <DestinationName>_Physics.prefab).
  5. Result: A Figure Prefab embedded with validated Spring / ColliderGroup physics structures is output and saved.
Figure 8: Source / Destination Configuration in Physics Transporter Tab
Figure 9: Validation Log Dialog Displayed during "Validate / Dry Run" Execution

Step 2: SpringBone Physics Transfer to Hair Outfit

  1. Change references in the Physics Transporter tab:
    • Source VRM Root: Original BasicFemaleHairAndSkirt.vrm
    • Destination Outfit Root: Scene Hair_ShapeSyncOutfit object created in Section 6
    • Destination Mode: Outfit
  2. [Mandatory Verification] Execute "Validate / Dry Run" to verify.
  3. Click "Transfer" and save via the Save dialog (Default candidate: <DestinationName>_PhysicsOutfit.prefab).

Step 3: [Interim Verification] Figure + Hair Outfit Runtime Check

  1. Place the physics-transported Figure in the scene and enter Play mode.
  2. Attach Hair_PhysicsOutfit using OutfitAttacher.TryAttach().
  3. Check Point: During walk animation playback, adjust the BasicGirl FBM slider (0.0 → 1.0) in DynamicBoneBlender and confirm hair sways dynamically according to Vrm10Instance.SpringBone physics calculations while conforming to body morphs.

Step 4: SpringBone Physics Transfer to Skirt Outfit

  1. Change references in the Physics Transporter tab:
    • Destination Outfit Root: Scene Skirt_ShapeSyncOutfit object created in Section 6
    • Destination Mode: Outfit
  2. [Mandatory Verification] Execute "Validate / Dry Run", then click "Transfer" to save via the Save dialog.

Step 5: Physics Normalization for Shirt Outfit

* Note (Physics Normalization): For final integration combined with a VRM Physics Figure, pass the Shirt through Physics Transporter in Outfit Mode as well. This normalizes remaining VRM-derived physics data and auxiliary bone information in the Outfit to only the actually used bones. Use this normalized output even if the Shirt itself contains no active SpringBones.

  1. Change references in the Physics Transporter tab:
    • Source VRM Root: Original BasicFemaleHairAndSkirt.vrm
    • Destination Outfit Root: Scene Shirt_ShapeSyncOutfit object created in Chapters 1 & 2
    • Destination Mode: Outfit
  2. [Mandatory Verification] Execute "Validate / Dry Run" to verify.
  3. Click "Transfer" and save the normalized physics outfit prefab as Shirt_PhysicsOutfit.prefab via the Save dialog.

8. Final Integration Checklist

As the conclusion to the guides up to this point, attach all parts constructed in Chapter 1 (tutorial_en.html), Chapter 2 (advanced_en.html), and Chapter 3 (vrm_en.html) in a scene to verify that each feature functions correctly in combination.

* Note: PBM (BreastSize morph), BC Profile (shoe pose correction), and PCM (foot clipping prevention) created in Chapter 2 (Advanced) are optional advanced features. They are not strict prerequisites for the VRM Guide itself.

Full Outfit Attachment Procedure

  1. Place the physics-transported VRM Figure in the scene.
  2. Enter Play mode and execute outfit attachment using OutfitAttacher:
    • Shirt (Tutorial): Shirt_PhysicsOutfit (normalized for physics in Step 5 of this chapter)
    • Shoes (Advanced - Optional): Shoes1_ShapeSyncOutfit (+ BCP + PCM created in Chapter 2)
    • Hair (VRM): Hair_PhysicsOutfit (+ SpringBone physics)
    • Skirt (VRM): Skirt_PhysicsOutfit (+ SpringBone physics)

Individual Verification Checklist

During walk animation playback in Play mode, verify each item individually and in combination:

  • FBM Body Deformation Check: Modify the BasicGirl FBM slider (0.0 ↔ 1.0) in DynamicBoneBlender and verify body and outfits deform seamlessly without mesh tearing.
  • VRM Expression Synchronization Check: Toggle expressions (e.g. Joy, Blink, AA) and verify facial expressions stay aligned without distortion even during FBM body morph changes.
  • SpringBone Swaying Physics Check: Verify hair and skirt Vrm10Instance.SpringBone physics sway naturally with walking movement and body shape changes.
  • Existing Outfit Attachment Check: Verify Chapter 1 Shirt and Chapter 2 Shoes attach to correct bone positions and conform to body deformation.

[Integration Success Result]:
An avatar equipped with all elements demonstrates seamless coordination: hair and skirt SpringBones sway naturally during walk animations, body morphs (FBM) and chest morphs (PBM) blend smoothly, shoe pose correction (BCP) and clipping prevention (PCM) function perfectly, and VRM expressions stay synchronized without breaking. Experience the complete, high-quality 3D avatar dressing system built across all 3 guides!

9. Troubleshooting & Key Notes

  • SHAPESYNC_USE_UNIVRM Symbol Missing Error:
    If the VRM Transporter window fails to open or compile errors occur, verify that SHAPESYNC_USE_UNIVRM is added to Scripting Define Symbols in Player Settings.
  • Scene Object Reference Requirement:
    For the ShapeSync Ready Figure, Base / FBM source VRM, and Renderers in Expression Baker, as well as Destination in Physics Transporter, assign Scene Objects or Prefab Mode roots. Project window Prefab assets cannot be assigned directly.
  • Asset Output Relative Folder Restriction:
    The VRM Asset Relative Folder restriction (disallowing leading Assets/ or parent references ../) applies to asset output configuration in VRM Initialize and Expression Baker (Physics Transporter uses its own Save file panel to select output destinations).
